BillMiner: Autonomous AI Agents & Open-Weight Models on Top of a Legacy ERP & Book Keeping System

A dental-supplies distributor kept its entire book keeping and accounting in Tally Prime (a desktop Legacy ERP), where the only way in or out is XML over HTTP across ~13,000 messy, clerk-typed stock names. I built BillMiner: an agentic operations and automated book keeping system that pulls that XML out of the Legacy ERP, builds a self-healing product catalogue, and runs production AI agents and open-weight models (Gemma 4 & Gemma 2B LoRA) on top of it — cutting inference costs dramatically by replacing expensive commercial APIs with open-weight models and ~25 ms edge lookups while posting paisa-exact XML book keeping vouchers back into Tally without changing how bookkeepers and accountants work.

Theme: XML in, intelligence out · Legacy ERP + Automated Book Keeping + Open-Weight Models + AI Agents

🚀 Autonomous AI Agents & Open-Weight Model Cost Reduction

Open-Weight LLMs & Cost Engineering

From Expensive Frontier APIs → Production Gemma 4 & Gemma 2B LoRA

Prototyped extraction and catalog matching on commercial frontier APIs, then systematically re-architected the stack around open-weight models and deterministic edge routing to eliminate per-token API bottlenecks and slash inference costs:

  • Gemma 4 in Production: Replaced commercial LLM calls on high-volume purchase bill line matching and variant resolution with open-weight Gemma 4, eliminating rate limits and per-bill API spikes.
  • Gemma 2B LoRA Judge (Fine-Tuning): Built the training dataset and fine-tuning pipeline for a compact Gemma 2B LoRA ranking judge designed to pick the winning SKU from the top-5 rule candidates at a fraction of large-model compute.
  • $0-Token Edge Routing & $0.007 Imagery: Offloaded known aliases and defining-word lookups to Cloudflare Workers + D1 (~25 ms/line) so models are only called on true ambiguity, and built a real-photo storefront pipeline at ~$0.007 per image instead of expensive generative image APIs.

Production AI Agent Fleet

4 Specialized Agents with Deterministic & Reversible Guardrails

Instead of a single fragile chat prompt, BillMiner runs four narrow, tool-using AI agents where every action is bounded by arithmetic checks, schema gates, and reversible audit logs:

  • 1. "Rao" (Retrieval Augmented Outvoicing Agent): In-workspace invoicing agent that takes pasted or photographed customer orders and writes structured lines straight onto the live bill with inline variant pickers, or drafts instant GST-inclusive price replies.
  • 2. Nightly Self-Learning & Catalogue Repair Agent: A nightly Cloudflare cron diffs raw OCR scans against final posted Tally vouchers to learn supplier aliases, followed by a scheduled Claude cloud agent that audits each bill and fixes catalogue cards through reversible, state-logged endpoints.
  • 3. Multi-Source Web Research Agent: Combines Brave Search API + LLM reader with manufacturer PDFs to verify missing product attributes across multiple independent sources before routing shelf-only unknowns to a 1-tap staff mobile queue.
  • 4. Read-Only Gmail Draft Agent: Monitors shared enquiry inboxes, runs Seller Detect against D1, and prepares quotation drafts without ever auto-sending unreviewed mail.

🧠 BillMiner AI, Dual-Reader OCR & Self-Learning Loops

Dual-Reader Purchase Bill Scanner

Supplier Invoice → Tally Purchase Voucher (92% End-to-End)

Reads multi-page photos or PDFs of supplier bills using two readers in parallel whose results are reconciled by arithmetic checks against the bill's printed taxable total:

  • Parallel Readers: Custom Vision OCR + rule-based table layout reader (handles tilted tables, 1.234,56 numbers, swapped qty/rate columns, and wrapped item names) alongside LlamaParse ("OCRia-1"). The reader whose line items sum to the printed taxable total wins.
  • Per-Supplier Notes & Gemma 4 Matching: Applies remembered supplier pack hints (re-verified by math) and matches each line to both its Tally stock item and catalogue card using Gemma 4.
  • Nightly Self-Learning Loop: A nightly Cloudflare cron compares scans with posted Tally vouchers to learn supplier aliases/rules (with fragment guards and full undo), and a scheduled Claude agent routine fixes catalogue cards via audited, reversible endpoints.

Edge Seller Detect + Rao Assistant

Customer Message → Tally Items (~25 ms/line) & "Rao"

Maps customer WhatsApp messages, Gmail enquiries, and photographed handwritten lists to exact Tally stock items at the edge on Cloudflare Workers + D1, paired with Rao ("Retrieval Augmented Outvoicing") inside the invoice screen:

  • Measured Edge Accuracy: WhatsApp orders hit 81% top-1 and 98% top-3; Gmail quotes hit 75% top-1 and 89% top-3 at ~25 ms/line. When unsure, offers 3 choices instead of guessing.
  • Defining Words & LoRA Judge: Steered by product nouns per Tally item, with a fine-tuned Gemma 2B LoRA judge (in progress) trained to rank top-5 candidates.
  • Rao Invoicing Assistant: Paste or photograph an order and Rao puts lines straight onto the bill with inline variant pickers, or generates plain-text GST-inclusive price replies without touching the active bill.

"Nothing Is Lost" Catalogue Engine

~13,000 Messy Tally Names → Family / Variant Cards

Reorganized ~13,000 clerk-typed Tally stock names (~9,600 sold) with misspellings, duplicates, and catch-all names into structured Product Families → Variants (catalogue cards):

  • Move, Never Delete: Every Tally name remains findable. Full pre/post set audits ensure zero lost keys; 3,256 never-billed dead names audited and marked in our DB without altering Tally.
  • Multi-Source Grounding: Manufacturer catalogues treated as truth, backed by Brave Search + LLM web verification across multiple sources.
  • Staff Micro-Questions: Shelf-knowledge gaps become quick mobile questions for staff while they wait on tasks — settling ~22% of catalogue gaps organically.

🔄 Architecture: The XML → LLM Pipeline

Tally Prime (desktop, XML/HTTP :9000) │ custom TDL reports, compact XML exports (≤500 KB per queued job; isolated date variables never disturb live billing) ▼ Windows Tally Agent ── job queue (pull sync, push XML vouchers with paisa-exact half-up GST rounding, print 4×6 labels) ▼ Firestore (app data) ⇄ Cloudflare D1 / KV (edge lookup ~25 ms/line: vouchers, stock items, aliases, catalogue cards) ▼ LLM + OCR Layer: Google Vision OCR · LlamaParse ("OCRia-1") · Gemma 4 · Gemma 2B LoRA (in progress) · Claude Routines · Brave Search ▼ Next.js Web App (Firebase App Hosting) + Cloudflare Workers APIs ▼ Back to Tally as XML: purchase vouchers, sales invoices, and new stock items (reconciles with Tally & GSTR-1 to the paisa)
